# App 版與網頁版的功能差異

> 盤點日期：2026-09-22（App v1.68.0 / `web/index.html`）。
> 兩邊共用同一份 Firestore 資料（`users/{uid}` 底下的 concerts / daily_songs / images / profile），
> 差的只有「哪些功能做在哪一邊」。改動任一邊的功能時，回來更新這張表。

盤點方式：逐條比對 App 的 `Screen` 路由（`presentation/navigation/Navigation.kt`）
與網頁的 `render*()` 函式，再以功能關鍵字交叉搜尋兩邊原始碼確認。

## 兩邊都有

| 功能 | App | 網頁 | 備註 |
| --- | --- | --- | --- |
| 演唱會清單 / 詳情 / 新增編輯 | ✓ | ✓ | 網頁的編輯欄位較少（沒有座位、取票資訊、多組開賣時間） |
| 行事曆（月曆） | ✓ | ✓ | |
| 每日選歌 | ✓ | ✓ | App 有感受標籤統計與 Spotify 搜尋 |
| 統計 | ✓ | ✓ | App 的圖表較多（縣市地圖、甜甜圈、里程碑） |
| 活動頁（免費活動 / 投稿 / 審核） | ✓ | ✓ | |
| 好友與共享日曆 | ✓ | ✓ | |
| 年度排行榜 | ✓ | ✓ | |
| 年度回顧 Wrapped | ✓ | ✓ | |
| 追蹤中的藝人 | ✓ | ✓ | |
| 垃圾桶（刪除的演唱會） | ✓ | ✓ | |
| 批量匯入（CSV / 貼清單） | ✓ | ✓ | |
| 匯出 CSV | ✓ | ✓ | App 端是 Pro 功能 |
| 管理員審核 / 爬蟲來源 | ✓ | ✓ | |
| 刪除帳號 | ✓ | ✓ | |

## 只有 App 有

| 功能 | 說明 |
| --- | --- |
| Bandary Pro / 付費 | Google Play Billing，網頁沒有付費機制 |
| 票根分享圖 / 統計分享卡 | `PosterRenderer`、`StatCardRenderer`，需要 Canvas 與相簿寫入 |
| 掃海報自動帶入 | ML Kit OCR |
| Google 日曆同步與匯入 | 需要 Google 授權與 Calendar API |
| 通知與提醒 | 入場提醒、開賣提醒、每日精選、補紀錄提醒 |
| 桌面小工具 | 四款 Glance 小工具 |
| 意見回饋表單 | 只有管理員讀得到 |
| 功能許願區 | v1.68.0 新增，公開許願 + 按讚 |
| 每月選歌回顧、里程碑徽章 | |
| Spotify 歌曲搜尋 | 經 Cloud Function 代理 |
| 照片（上傳、封面、場位圖、節目表） | 網頁不處理照片，只看得到資料 |

## 只有網頁有

目前沒有「網頁獨有」的功能。網頁是 App 的子集，定位是「在電腦上補資料、看統計」。

## 已經從兩邊都移除

| 功能 | 移除版本 | 原因 |
| --- | --- | --- |
| 音樂祭時程表 | v1.68.0 | App 端的兩個畫面（`FestivalTimetableScreen`、`FestivalImageScreen`）早已沒有任何入口叫得到，是殘留死碼；網頁端一併移除以保持一致。`Concert.festivals`（卡司清單）保留——統計、追蹤藝人、好友日曆、活動投稿都靠它，且舊資料裡帶時間/舞台的 slot 在編輯時原樣保留，不主動刪。 |

## 已知的不一致（待處理）

- **網頁的演唱會編輯欄位比 App 少**：座位、取票序號/機台、多組開賣時間、提醒設定、逐場日曆同步在網頁上都沒有；在網頁存檔時會保留這些欄位不動（`web/index.html` 的 `saveConcert` 只寫有動到的欄位），所以不會洗掉手機填的資料。
- **網頁沒有照片**：從網頁存檔不會動到 `photoUris` 等欄位，但也看不到照片。
- **統計的圖表組合兩邊不同**：網頁少了縣市地圖、里程碑與部分甜甜圈圖。
